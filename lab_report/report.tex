\subsection{第1题：含空格文件名的批量整理}
\taskmeta{Shell 基础与文件系统}

\subsubsection{任务说明}

创建 q01，使用命令行完成目录与文件创建、隐藏文件查看、按扩展名复制文件、权限设置以及清单生成。

\subsubsection{关键操作}

使用mkdir -p创建input文件夹以及所包含的文件；使用printf“...”输入文件内容；使用touch创建文件；使用ls -laR查看input中所有文件：

\begin{lstlisting}[style=terminal]
mkdir -p input/docs input/tmp
printf "alpha\nbeta\n" > "input/docs/notes one.txt"
printf "hidden\n" > input/docs/.secret.txt
touch input/tmp/empty.txt
printf "start\nfinish\n" > input/run.log
ls -laR input
\end{lstlisting}

随后查找所有 \texttt{.txt} 文件，并在复制时保留相对目录结构：

创建work/25020007046文件夹；使用find找寻所有.txt类型的文件；使用-exec找到一个文件后执行cp复制操作；--parents保留原来的路径结构：

\begin{lstlisting}[style=terminal]
mkdir -p work/25020007046
find input -type f -name "*.txt" \
  -exec cp --parents "{}" work/25020007046 \;
\end{lstlisting}

设置目录与普通文件权限，并生成文件清单：

使用chmod改变文件权限；-type d找目录，-type f找文件； \texttt{\%}P会保留相对路径；\texttt{\%}s显示文件大小：

\begin{lstlisting}[style=terminal]
find work/25020007046 -type d -exec chmod 750 {} \;
find work/25020007046 -type f -exec chmod 640 {} \;
find work/25020007046 -type f \
  -printf "%P %s\n" > inventory.txt
cat inventory.txt
\end{lstlisting}

\noindent{\small\textbf{关键点：}}
\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
  \small
  \item 文件名中包含空格时，要用双引号把完整路径括起来；查看隐藏文件要使用 \texttt{ls -a}。
  \item \texttt{ls -laR input} 中，\texttt{-l} 是长格式，\texttt{-a} 显示隐藏文件，\texttt{-R} 递归查看子目录。
  \item \texttt{find} 用来查找文件，\texttt{cp --parents} 可以在复制时保留原来的目录结构。
  \item 权限数字由 可读\texttt{r=4}、可写\texttt{w=2}、可进入\texttt{x=1} 相加得到；本题目录使用 750，普通文件使用 640。
\end{itemize}

\subsection{第2题：随机访问日志统计}
\taskmeta{Shell 管道与文本处理}

\subsubsection{任务说明}

编写 \texttt{analyze.sh}，对 CSV 日志进行统计：输出 HTTP 5xx 数量最多的前 2 个 path，并计算全部数据行的平均延迟；同时处理输入文件不存在的异常情况。

\subsubsection{脚本实现}

\begin{lstlisting}[style=source,language=bash]
#!/bin/bash

if [ ! -f "$1" ]; then
    echo "Error: file not found: $1" >&2
    exit 1
fi

echo "Top 2 5xx paths:"
awk -F',' 'NR > 1 && $4 >= 500 && $4 < 600 {
    count[$3]++
} END {
    for (p in count) print count[p], p
}' "$1" | sort -k1,1nr -k2,2 | head -2

echo "Average latency_ms:"
awk -F',' 'NR > 1 {
    sum += $5; count++
} END {
    printf "%.2f\n", sum/count
}' "$1"
\end{lstlisting}

\noindent{\small\textbf{关键点：}}
\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
  \small
  \item 使用if判断是否是文件，fi结束判断。
  \item \texttt{\$1} 表示脚本接收的第一个参数；\texttt{>\&2} 把错误信息输出到 stderr，\texttt{exit 1} 表示脚本执行失败，可使用echo \texttt{\$?}查看错误输出。
  \item \texttt{awk -F','} 用逗号分隔 CSV 字段，\texttt{NR>1} 用来跳过表头。
  \item CSV 每一行有 5 列：\texttt{\$1=09:00:05 \$2=bob \$3=/api/orders \$4=502 \$5=260}。
  \item count\texttt{[\$3]++}表示计数将路径计数一次。for(p in count)：把count里面的每一个 path 都拿出来；print count[p], p：打印path的次数和path。
  \item 管道符 \texttt{|} 会把前一个命令的输出交给下一个命令，本题依次使用 \texttt{awk}、\texttt{sort} 和 \texttt{head} 完成统计与排序。sort -k1,1nr -k2,2表示依据第一列降序排序；head -2只取前两行。
  \item 运行\texttt{./analyze.sh access.csv}时，\texttt{.analyze.sh}是运行脚本，\texttt{access.csv}是传给脚本的第一个参数；默认参数使用\texttt{"\$1"}。
\end{itemize}

\subsection{第3题：制造、解决并解释一次合并冲突}
\taskmeta{Version Control and Git}

\subsubsection{任务说明}

从零初始化 Git 仓库，通过两个分支对同一行进行不同修改，主动制造合并冲突；随后按题目要求解决冲突，并检查最终提交历史。

\subsubsection{关键过程}

使用git init初始化仓库；使用git status查看仓库情况，可发现正在main分支上；使用git add将文件转入暂存区；使用git commit -m(提交说明)提交。

\begin{lstlisting}[style=terminal]
git init
git status
echo "mode=normal" > config.txt
git add config.txt
git commit -m "initial commit"
\end{lstlisting}

使用git switch -c feature-x创建两条新的分支；使用git switch可切换分支；在feature-a分支上将文件改为mode=safe，进行git add以及git commit；在分支feature-b上将文件改为mode=fast；返回main分支先合并feature-a，git merge feature-a；在合并feature-b出现合并冲突。

\begin{lstlisting}[style=terminal]
git switch -c feature-a
echo "mode=safe" > config.txt
git add config.txt
git commit -m "set mode to safe"
git switch main
git switch -c feature-b
git add config.txt
git commit -m "set mode to fast"
git switch main
git merge feature-a
git merge feature-b
\end{lstlisting}

冲突后文件内容变为：

\begin{lstlisting}[style=terminal]
<<<<<<< HEAD
mode=safe
=======
mode=fast
>>>>>>> feature-b
\end{lstlisting}


发生冲突后，将 \texttt{config.txt} 最终修改为：

\begin{lstlisting}[style=terminal]
cat > config.txt
 mode=safe
 note=reviewed
git add config.txt
git commit -m "merge feature-b and resolve conflict"
\end{lstlisting}

完成冲突解决后检查提交图：

\begin{lstlisting}[style=terminal]
git status
git log --all --graph --decorate --oneline
\end{lstlisting}

\noindent{\small\textbf{关键点：}}
\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
  \small
  \item Git 的基本过程可以理解为“工作区 $\rightarrow$ 暂存区(add) $\rightarrow$ 提交历史(commit)”。
  \item 两个分支修改同一位置时可能产生冲突，需要人工决定最终内容，并删除冲突标记。
  \item \texttt{git status} 用来检查工作区状态，\texttt{git log --all --graph --decorate --oneline} 用来查看分支和提交历史。
\end{itemize}

  y=ax+b

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
