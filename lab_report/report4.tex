\subsection{第13题：建立可执行的本地质量门禁}

\taskmeta{代码质量}

\subsubsection{任务说明}

在 pyproject.toml 中加入 ruff 和 pytest 配置，补充正常姓名和空白姓名测试，运行 ruff format、ruff check、pytest，并编写 check.sh 一键执行检查。

\subsubsection{关键操作}

加入ruff以及pytest的最小配置；补充一个正常姓名测试和一个空白姓名测试，每个测试包含有效断言；

\begin{lstlisting}[style=source]
#pyproject.toml
[tool.ruff]
line-length = 88
[tool.pytest.ini_options]
testpaths = [
    "tests"
]

#cli.py
import argparse
def main():
    p = argparse.ArgumentParser()
    p.add_argument("--name", required=True)
    a = p.parse_args()
    if not a.name.strip():
        raise SystemExit(2)
    print(f"Hello, {a.name}!")
if __name__ == "__main__":
    main()

#test_cli.py
import pytest
from greetlab.cli import main
def test_empty_name(monkeypatch):
    monkeypatch.setattr(
        "sys.argv",
        ["sdt-greet", "--name", "   "]
    )
    with pytest.raises(SystemExit):
        main()
\end{lstlisting}


编写check.sh，依次执行ruffformat--check、ruff check 和 pytest；运行并保证返回0：

\begin{lstlisting}[style=source]
#!/usr/bin/env bash
set -e
ruff format --check
ruff check
pytest
\end{lstlisting}

运行ruffformat、ruff check 和 pytest，修复全部问题：

\begin{lstlisting}[style=terminal]
chmod +x check.sh
ls -l check.sh

ruff format ruff自动调整书写规范
ruff check 检查代码质量问题
ruff format
./check.sh
\end{lstlisting}

\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item \texttt{ruff format}：自动规范 Python 代码格式，\texttt{--check} 参数只检查不修改。
    \item \texttt{ruff check}：静态检查代码问题，例如未使用变量、代码规范错误等。
    \item \texttt{pytest}：自动执行测试用例，通过断言验证程序行为是否符合预期。
    \item \texttt{SystemExit(2)}：用于表示空白姓名属于非法输入，测试时需要检查退出码。
    \item \texttt{capsys} 可以捕获程序输出，用于验证正常输入时是否输出正确问候语。
    \item \texttt{check.sh} 使用 \texttt{set -e}，保证任意一步检查失败后立即停止执行。
\end{itemize}

\subsection{第14题：让Make只重建真正受影响的产物}

\taskmeta{元编程；构建系统}

\subsubsection{任务说明}

使用 Makefile 管理一个简单的数据处理流程，让 Make 自动判断：哪些文件已经生成或变化，哪些目标需要重新执行。

\subsubsection{关键操作}

创建Makefile：

\begin{lstlisting}[style=source]
.PHONY: all clean

all: report.txt

stats.txt: data.csv stats.py
	python stats.py

report.txt: report.md stats.txt build_report.py
	python build_report.py

clean:
	rm -f stats.txt report.txt
\end{lstlisting}

\noindent{\small\textbf{解释代码：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item \texttt{.PHONY: }all clean ：声明 all 和 clean 为伪目标（Phony Target）。
        因为all 和 clean 不是实际生成的文件；它们只是用于执行构建任务的命令入口。通过声明为 .PHONY，可以避免 Make 将它们误认为文件，从而保证make clean都会执行清理操作。
    \item all: report.txt ：定义默认构建目标。执行make时，Make默认执行第一个目标all。
        由于all依赖report.txt因此Make会检查并生成最终报告。
    \item \texttt{stats.txt:} data.csv stats.py  python stats.py ：定义 stats.txt 的生成规则；其中依赖文件：data.csv，stats.py；目标文件：stats.txt。
    \item \texttt{report.txt:} report.md \texttt{stats.txt} build\_report.py   python build\_report.py ：定义最终报告文件的生成规则，生成\texttt{report.txt}需要report.md，\texttt{srars.txt}，build\_report.py。
    \item clean:    rm -f stats.txt \texttt{report.txt} ：执行make clean会删除由构建过程生成的文件\texttt{stats.txt}和\texttt{report.txt}。

\end{itemize}

\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item Make 是一种自动化构建工具，通过定义目标文件（target）、依赖文件（dependency）和生成命令，实现自动判断是否需要重新构建。
    \item 第一次执行 \texttt{make} 时，Make 根据依赖关系依次执行\texttt{stats.py} 和 \texttt{build\_report.py}，生成\texttt{stats.txt} 和 \texttt{report.txt}。
    \item 第二次执行 \texttt{make} 时，由于源文件未发生变化，所有目标文件均为最新状态，因此无需重新执行构建命令。
    \item 当源文件未修改时，再次执行 \texttt{make} 不会重复执行命令，提高构建效率。
    \item Makefile 中命令行前必须使用 Tab 缩进，不能使用普通空格，否则会出现 \texttt{missing separator} 错误。
\end{itemize}

\subsection{第15题：把本地API数据转换为可读报告}

\taskmeta{大杂烩：API、jq、CLI约定与Markdown}

\subsubsection{任务说明}

创建本地 JSON 数据文件，并通过 Python HTTP 服务模拟 API 接口；使用 \texttt{curl} 获取 HTTP 返回的数据；
使用 \texttt{jq} 对 JSON 数据进行筛选和排序；编写 \texttt{api\_report.sh} 自动生成 Markdown 格式的数据报告。

\subsubsection{关键操作}

运行python-mhttp.server 8000，使用curl-fsS获取http://127.0.0.1:8000/packages.json；

\begin{lstlisting}[style=source,language=bash]
python -m http.server 8000
打开另一个窗口，测试 jq 是否能读取JSON：
curl http://127.0.0.1:8000/packages.json
\end{lstlisting}

使用jq筛选status为active且downloads不少于100的记录，并按downloads降序、name升序排列；
编写api\_report.sh，把结果生成summary.md，包含标题和name/version/downloads三列表格：

\begin{lstlisting}[style=source]
#测试筛选功能
curl http://127.0.0.1:8000/packages.json | jq '
.[] 
| select(.status=="active" and .downloads>=100)
'
#加排序
curl http://127.0.0.1:8000/packages.json | jq '
[
  .[]
  | select(.status=="active" and .downloads>=100)
]
| sort_by(-.downloads, .name)
'
\end{lstlisting}

编写 api\_report.sh，把结果生成 summary.md，包含标题和 name/version/downloads 三列表格：

\begin{lstlisting}[style=source,language=bash]
#api_report.sh

#!/usr/bin/env bash

curl -fsS http://127.0.0.1:8000/packages.json |
jq -r '
[
  .[]
  | select(.status=="active" and .downloads>=100)
]
| sort_by(-.downloads, .name)
|
(
"# Package Summary\n\n" +
"| name | version | downloads |\n" +
"|---|---|---|\n" +
(map("| \(.name) | \(.version) | \(.downloads) |") | join("\n"))
)
' > summary.md
\end{lstlisting}


\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item \texttt{curl} 用于从本地 HTTP 服务获取 JSON 数据。
    \item \texttt{jq} 用于处理结构化 JSON 数据，相当于 JSON 数据处理工具。
    \item \texttt{select()} 用于根据条件筛选对象。
    \item \texttt{sort\_by()} 用于按照指定字段排序。
    \item 管道符 \texttt{|} 将前一个命令的输出传递给下一个命令，实现数据处理流程自动化。
\end{itemize}

编写Makefile，实现代码检查、项目构建和清理操作；使用\texttt{python -m build}生成wheel安装包，并计算SHA-256校验值完成发布验证。

\subsubsection{关键操作}

复制q13为q16并初始化/继续使用Git；把问候语实现临时改成始终返回字面量Hello,name!，运行check.sh确认测试失败；随后定位并修复：

制造并定位程序错误：

\begin{lstlisting}[style=terminal] 
#cli.py
import argparse
def main():
    p = argparse.ArgumentParser()
    p.add_argument("--name", required=True)
    a = p.parse_args()

        raise SystemExit(2)

    main()

q16是新的项目副本，需要重新进行安装；并使用pytest发现问题：

\begin{lstlisting}[style=terminal]

\end{lstlisting}

\begin{lstlisting}{style=terminal}

\begin{lstlisting}{style=terminal}
make build
\end{lstlisting}


\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
  \small
  \item \texttt{pip install -e .}：可编辑安装方式，使命令入口指向当前源码，方便开发调试。
  \item 制造bug后通过\texttt{pytest}失败结果分析错误原因，再修改源码完成修复。
  \item \texttt{Makefile}用于自动化管理项目流程，将检查、构建、清理等操作封装为简单命令。
  \item \texttt{make check}整合格式检查、静态检查和测试，提高代码提交前的可靠性。
  \item \texttt{python -m build}用于生成Python发布包，其中wheel文件可通过pip直接安装。
  \item SHA-256校验值用于验证构建产物完整性，保证发布文件未被修改。
\end{itemize}

\section{问题与总结}

\subsection{遇到的问题}

\begin {itemize}[leftmargin=2em]
\item \textbf {命令入口无法识别：}
第 13 题配置 \texttt {pyproject.toml} 后直接运行 \texttt {sdt-greet --name Alice}，
出现 \texttt {command not found}。原因是项目虽然配置了脚本入口，
但当前环境没有安装该项目。通过执行 \texttt {pip install .} 安装项目，
使系统生成对应命令入口，之后可以正常调用 \texttt {sdt-greet}。
\item \textbf {修改源码后命令仍执行旧版本：}
第 16 题从 q13 复制项目到 q16 后，修改了源码中的问候语输出，
但运行 \texttt {sdt-greet} 仍得到旧结果。原因是之前安装的命令入口仍指向旧项目。
使用 \texttt {pip install -e .} 进行可编辑安装，使命令入口重新绑定当前源码目录，
修改后的代码能够及时生效。
\item \textbf {pytest 无法通过命令执行：}
第 13、16 题运行检查脚本时出现 \texttt {pytest: command not found}。
检查发现 Python 环境中已经安装 pytest，但终端无法直接找到对应命令。
将脚本中的 \texttt {pytest} 修改为 \texttt {python -m pytest}，
通过 Python 模块方式调用测试工具，提高了环境兼容性。
\item \textbf {ruff 格式检查失败：}
第 13 题第一次运行 \texttt {./check.sh} 时，
ruff 提示部分 Python 文件需要重新格式化。
使用 \texttt {ruff format} 自动调整代码格式，
再运行 \texttt {ruff format --check} 验证，
最终所有文件通过格式检查。
\item \textbf {Makefile 命令执行逻辑不理解：}
第 14 题编写 Makefile 时，对 \texttt {make}、目标 (target) 以及依赖关系理解不足。
通过分析 Makefile 中的规则，例如 \texttt {check} 调用检查脚本，
\texttt {build} 调用构建命令，
理解了 Makefile 可以将多个重复操作封装成简单命令，提高项目管理效率。
\item \textbf {curl 无法连接本地服务：}

\texttt {curl[http://127.0.0.1:8000/packages.json](http://127.0.0.1:8000/packages.json)}
时提示无法连接服务器。
检查发现本地 HTTP 服务没有启动。
使用 \texttt {python -m http.server 8000} 启动服务后，
curl 能够正常获取 JSON 数据。
\item \textbf{理解 jq 筛选与排序逻辑困难：}
第 15 题中需要筛选 active 状态且 downloads 不少于 100 的数据，
同时按照下载量降序、名称升序排列。
通过学习 \texttt{.[]} 遍历数组、
\texttt{select()} 条件过滤以及 \texttt{sort\_by()} 排序，
理解了命令行工具处理结构化数据的流程。
\item \textbf{SHA-256 校验作用不理解：}
第 16 题计算 wheel 文件哈希值时，
不清楚随机字符串的意义。
通过了解 SHA-256 后认识到其相当于文件数字指纹，
可以用于验证发布文件是否被修改，保证软件交付完整性。
\end{itemize}



\subsection{实验总结}

本周实验综合实践了软件开发的完整工程流程，涵盖代码修改、自动化测试、项目构建与发布验证。通过人为制造问候语输出错误，体验了测试驱动的问题定位过程，认识到测试不仅能证明程序正确，还能帮助快速发现逻辑错误。
实验中进一步学习了 Makefile 自动化工具，将检查、构建等重复操作封装为简单命令，提升了项目管理效率；同时通过 wheel 构建和 SHA-256 校验，了解了 Python 项目从源码开发到软件交付的基本流程。
过程中遇到了 Python 包安装路径、命令入口更新、pytest 环境配置等问题，通过查阅报错、分析运行流程并修改配置，逐渐理清了开发环境、测试工具与构建工具之间的关系。
经过最后一周实验，对软件工程中 "开发 — 测试 — 修复 — 构建 — 发布" 的完整流程有了更系统的认识，也提升了运用 Git、Python 工具链及自动化脚本解决实际问题的能力。
