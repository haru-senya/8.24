\subsection{第10题：让编程智能体进入可验证的修复循环}

\taskmeta{智能体编程}

\subsubsection{任务说明}

本实验要求在第 9 题 Python 命令行工具的基础上，引入自动化测试流程。通过添加测试用例发现程序缺陷，利用编程智能体分析问题并修改代码，最后通过测试验证修复结果。

\subsubsection{关键操作}

创建 q10 项目（复制q09），编写测试文件夹tests以及测试文件test\_cli.py，并运行，发现首次运行失败：

\begin{lstlisting}[style=source]
#tests/test_cli.py
import pytest
from greetlab.cli import main

def test_empty_name(monkeypatch):
    monkeypatch.setattr(
        "sys.argv",
        ["sdt-greet", "--name", "   "]
    )

    with pytest.raises(SystemExit):
        main()
\end{lstlisting}

其中with pytest.raises(SystemExit):  main()表示测试要求当输入只有空白字符时，程序应该异常退出。如果程序没有退出，则测试失败。


\begin{lstlisting}[style=terminal]
pytest

Failed: DID NOT RAISE <class 'SystemExit'>
\end{lstlisting}

表示当前程序没有处理空白参数，需要进行代码修复。

修改程序增加输入检查，使用 strip() 删除字符串两端空格，当输入为空白字符时退出程序，避免无效输入：

\begin{lstlisting}[style=source]
import argparse

def main():
    p = argparse.ArgumentParser()
    p.add_argument("--name", required=True)
    a = p.parse_args()

    if not a.name.strip():
        raise SystemExit(2)

    print(f"Hello, {a.name}!")

if __name__ == "__main__":
    main()
\end{lstlisting}


\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item 测试驱动修复流程：发现问题->编写测试->运行失败->修改代码->测试通过
    \item pytest 可以自动执行测试用例，帮助快速发现程序错误。
    \item SystemExit 用于让命令行程序返回错误状态。
    \item strip() 可以去除字符串中的空格，用于判断用户输入是否有效。
    \item 自动化测试可以降低人工检查成本，提高代码可靠性。
\end{itemize}

\subsection{第12题：修复一个可复现的线性回归训练循环}

\taskmeta{Python与PyTorch}

\subsubsection{任务说明}

本实验使用 PyTorch 完成一个简单线性回归训练任务，通过梯度下降优化模型参数，使模型学习目标函数 y=3x-1。

\subsubsection{关键操作}

补全训练循环，调用zero\_grad、backward、step；训练后用model.eval()，并在torch.no\_grad()中计算最终损失；打印最终损失weight bias：

\begin{lstlisting}[style=source] 
import torch
from torch import nn
torch.manual_seed(20260907)
x = torch.linspace(-1, 1, 101).reshape(-1, 1)
y = 3 * x - 1
model = nn.Linear(1, 1)
loss_fn = nn.MSELoss()
opt = torch.optim.SGD(model.parameters(), lr=0.1)
for _ in range(200):
    pred = model(x)
    loss = loss_fn(pred, y)
    opt.zero_grad()
    loss.backward()
    opt.step()
model.eval()
with torch.no_grad():
    pred = model(x)
    final_loss = loss_fn(pred, y)
    print("loss:", final_loss.item())
    print("weight:", model.weight.item())
    print("bias:", model.bias.item())
\end{lstlisting}


\noindent{\small\textbf{代码解释：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item model = nn.Linear(1, 1) 创建线性模型，数学形式$y = wx + b$，w、b不知道，需要训练。
    \item loss\_fn = nn.MSELoss() 定义损失函数，计算预测值和真实值之间差多少。
    \item opt = torch.optim.SGD(model.parameters(),lr=0.1) 优化器，SGD随机阶梯下降；作用：根据错误方向调整weight、bias。
\end{itemize}


\noindent{\small\textbf{三个TODO：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item 清空梯度：opt.zero\_grad()，每轮训练开始要清空。
    \item 反向传播：loss.backward()，损失函数对于参数的梯度。
    \item 更新参数：opt.step()，根据梯度修改weight、bias。
    \item 进入评估模式：model.eval()，表示模型现在不是训练状态。
    \item 不计算梯度：with torch.no\_grad(): 只是查看结果，不训练。
    \item 计算最终结果：with torch.no\_grad():pred = model(x) final\_loss = loss\_fn(pred, y) print("loss:", final\_loss.item()) print("weight:", model.weight.item()) print("bias:", model.bias.item())
\end{itemize}


\noindent{\small\textbf{关键点：}}

\begin{itemize}[leftmargin=2em,itemsep=0.2em,topsep=0.3em]
    \small
    \item PyTorch 训练流程通常包括：前向传播、计算损失、反向传播、参数更新。
    \item 梯度是模型优化的重要依据。
    \item 训练阶段和评估阶段需要区分。
    \item 不能直接给 weight 和 bias 赋值，需要通过优化过程学习参数。
\end{itemize}

\section{问题与总结}

\subsection{遇到的问题}

\begin{itemize}[leftmargin=2em]

\item \textbf{Python 环境中缺少依赖：}
在完成 q09 时运行 \texttt{python -m build} 时提示 \texttt{No module named build}。
检查发现当前 Python 环境中没有安装构建工具，因此使用 \texttt{pip install build} 安装。
安装过程中由于网络访问 PyPI 较慢，切换到国内镜像源后成功完成安装。

\item \textbf{Python 模块导入错误：}
q10 测试实验中运行 pytest 时出现 \texttt{ModuleNotFoundError}。
检查项目结构后发现测试环境无法找到对应模块。
通过调整项目目录结构和安装方式，使测试代码能够正确导入目标模块。

\item \textbf{pytest 测试失败定位问题：}
在 q10 中第一次运行测试时，测试未通过，提示空字符串输入情况下程序没有抛出 \texttt{SystemExit}。
根据测试信息定位到参数校验逻辑缺失，修改代码后重新运行 pytest，最终测试通过。
通过该过程理解了测试驱动开发中“发现问题—修改代码—重新验证”的流程。

\item \textbf{训练结果输出位置错误：}
初次运行 q12 时，将 loss、weight 和 bias 的输出放在训练循环内部，导致终端输出大量重复信息。
调整代码结构，将最终结果输出移动到训练结束后的评估阶段，使输出符合实验要求。

\end{itemize}

通过本次实验，我进一步熟悉了 Python 项目开发过程中的工具链使用，包括项目打包、虚拟环境管理、自动化测试以及深度学习环境配置。

在 q09 实验中，我学习了如何通过 \texttt{pyproject.toml} 配置 Python 项目，并使用 \texttt{python -m build} 生成 wheel 包，再通过独立虚拟环境完成安装验证，理解了 Python 项目从源码到可发布包的基本流程。

总体来说，本次实验不仅提升了对 Python 工程化开发工具的使用能力，也让我认识到软件开发不仅需要实现功能，还需要关注环境管理、自动化测试、代码规范和问题定位能力。在后续学习中，需要继续加强对开发工具链和工程实践流程的掌握。
